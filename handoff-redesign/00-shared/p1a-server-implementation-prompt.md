# P1a self-driving prompt — server-authoritative backend 実装 (Node + better-sqlite3 + API) 【v1.0、2026-06-03】

> postv5 の最初の実装フェーズ。**P0 preflight は承認済 + Codex 4-round review 収束済** (`postv5-p0-preflight-contract.md`、ratified SD-1..SD-5)。本 prompt は P1a の self-driving 実行指示。**設計の権威は P0 契約 (`postv5-p0/01..10.md`)** — 本 prompt は DDL/列定義を複製せず契約を spec として参照する。契約と本 prompt が食い違う場合は契約が優先 (drift を見つけたら停止して報告)。

## Goal
backoffice-ai-v2 prototype (branch: `main`、greenfield v2 = 静的 SPA、reducer + localStorage) に **server-authoritative な backend を新設**する。P1a の完了状態 = **server 側で SoD / propose-execute 分離 / append-only audit / governance read-only / IDOR / injection 防御が *実装され、in-process server test で falsifiable に証明されている*。client は不変** (まだ reducer + localStorage のまま。API 配線は P1b)。

## P1a スコープの定義 (誤読防止)
- **"minimal parity seed" の "minimal" は seed の *量* を指す** (P2 の realistic volume と対比)。**endpoint 面は minimal ではない** — **24 行の mutation matrix (`04 §B`) のうち server endpoint 化するのは 22**（persona switch [#23] は専用 endpoint を持たず per-write body `{ actorId }` の検証のみ; store/hydrate・store/reset [#24] は endpoint 化せず、reset は CLI `db:reset-demo` のみ・HTTP reset は OUT-OF-P0）+ 必要な read endpoint を *全て*実装する。理由: P1a gate の SoD/audit 不変条件 test は enforcement が real でないと書けず、P1b (client adapter) は full API surface に対して配線するため。`/api/session/switch` や HTTP reset endpoint は **新設しない**（`04 §B` row 23/24 + `06 §契約3` + `09 §4`）。
- **client は触らない** (`src/v2/*`・`src/store/*` reducer/localStorage は不変)。server を叩くのは in-process server test のみ (#5/#9: in-process handler invocation、Vitest node project、supertest/HTTP client 不使用)。
- deploy (pages.yml/README)・data 拡充・role UI・selector は P1a 対象外 (下記 §Out of Scope)。

## 不可侵 (P0 から継承)
1. **mock core 不変**: 実 LLM / 実 OCR / 実顧客データ / 実 PDF / 実外部銀行接続 / 実規制 cite は無し。AI 出力は seed/mock のまま。server は *統制の enforcement* だけを real にする。
2. **視覚方向不変**: client UI は P1a で変えない (v2 light operator console、token/lucide/chip/tone v2/status-tones/JP-only)。
3. **規制業務セマンティクス不変**: 四眼 SoD (入力者≠承認者)、propose/execute 分離、honest framing、**confidence 生数字は static governance 台帳 (`OBS_LEDGER`/`CROSS_LEDGER`、governance role read) のみ、operational `audit_events` には confidence 列を持たない** (`08(b)` + `09 §3-1`)、PrototypeModeLabel。
4. 機能を落とさない (落とす場合は停止して user 承認)。
5. main 置換は user 最終承認 gate。P1a は **branch `postv5/p1a-server` → PR → 承認**。

## 設計原則 — prototype-appropriate rigor (最優先)
各統制は「規制レビュアーに見せて筋が通る最小実装 + それを破る試みを拒否する server test」で足りる。**full auth framework / IdP / RBAC engine / prod infra / 監視 stack / SIEM / anomaly detection は作らない**。迷ったら「これは統制の *実証* に必要か、それとも production hardening か」を問い、後者なら入れない。過剰設計の兆候 (新規 framework、抽象層増殖) は stop して再 right-size。

## アーキテクチャ (P0 契約の要点、詳細は各契約参照)
- **stack** (`07-package-layout.md`): server dir = `prototype-redesign/server/`、**Node ピン = `.nvmrc`=24 新規作成 / `engines.node>=22` (上限ピン無し — local 25.x を EBADENGINE で弾かない、`07 §4`)** + Express 5 + better-sqlite3 + zod (server runtime deps = 3)。server 専用 tsconfig。`vite.config` 用の `tsconfig.node.json` とは別。
- **identity** (`03-auth-session.md` = canonical、SD-1): dual-identity。`X-Operator-Token` (HMAC-SHA256、payload `operator_id.issued_at.expires_at.jti`、expiry 30 min、replay reject = in-memory `Set<jti>`、operator 再 login で旧 jti revoke)。secret env `BOAI_SESSION_SECRET` 1 個。operator login = `POST /api/session/operator` (2 demo operator `op-demo-1`/`op-demo-2` は CODE CONSTANT)。persona = per-write body `{ actorId }` を `allowed_actors` (5 seeded actors = 3 operational + ≥2 governance) に validate。**SoD subject = `effective_actor_id`** (persona)。`session_operator_id` は provenance のみ (両者を audit に NOT NULL 記録)。専用 persona switch endpoint は作らない。
- **authorization** (`09-security.md` + `02-auth-role.md`、SD-2): governance role = READ-ONLY (全 mutation reject) + governance-only read endpoint を他 role に reject + object-level IDOR (`denialReason='NOT_FOUND'`→404)。operational execute (24 行 matrix のうち endpoint 化される 22 mutation) = identity-SoD + prior-state のみ (per-action role gate なし)。`ActorRole` に `'governance'` を additive 追加。
- **mutation semantics** (`04-mutation-matrix.md` = per-action SSOT): 全 mutation は `{ ok, entity?, auditEvent?, denialReason? }` を返す pessimistic default。全 write body は `ActorPersonaBody { actorId }` ⊕ command 固有 field を zod `.strict()` で検証。denial = `{ ok:false, denialReason:<ENUM> }` (default 403、IDOR のみ 404)。
- **data model** (`08-data-model.md` = DDL SSOT): SQLite 単一ファイル (WAL)。21 table。全 connection で `PRAGMA foreign_keys=ON; journal_mode=WAL; busy_timeout=5000` (startup test で検証)。enum = TEXT + CHECK。FK `ON DELETE RESTRICT`。`audit_events` は append-only (`BEFORE UPDATE/DELETE RAISE(ABORT)` trigger + seq 単調増)。KPI = `synthetic_metric_rows` (seed 固定) vs `operational_count_views` (view 派生)。`demo_clock` 単一行 (`NOW_ISO` 移植)、occurred_at = deterministic `auditTs(seq)` tz-aware ISO (runtime wall-clock 不使用)。`historical_cases` (#21、proposal source-case FK 整合)。
- **DB operation** (`06-db-ops.md`): forward-only migration + `schema_migrations(version,name,applied_at,checksum)` + 各 migration に rollback NOTE + 冪等 seed + `db:reset-demo` (env-gated、no HTTP、DB recreate)。全 mutation は **transaction 内で domain row 更新 + `audit_events` INSERT を atomic に**。
- **observability**: structured log は dual-ID allowlist (`session_operator_id`/`effective_actor_id`/`action`/`ok|deny`/`denialReason`、`01 §B-1` #8) のみ、`GET /api/health`、DB open 失敗時 fatal exit。
- **test surface** (`05-test-migration.md` + `09-security.md`、R11): server invariant/security test は **in-process handler invocation** (Vitest node project)。HTTP を立てない。supertest 不使用。real-HTTP smoke は P1b 以降の thin Playwright 層。

## Verification gates (各 gate は mechanical/falsifiable に)
- **`check:server` green** = server types + unit/API test (in-process)。最終的に `check:all` (client lint/types/test/build + `check:server`) に統合。
- **server invariant test (必須、in-process)** — named-test SSOT = `04 §D` + `09 §1-3/§2-3/§3`、本 prompt は collapse せず網羅する:
  - **SoD/四眼**: 自己承認拒否 (case-checker / proposal-approve / promotion-approve) + escalation 非指名裁定者 reject + mutation-side `idor-actor-spoof-mutation` (body actorId 詐称を server-resolved effective_actor_id で再判定)。
  - **identity**: token 無し/改竄/期限切れ/revoked-jti reject + unknown-actor reject + body actorId が `session_operator_id` を変えない + operator≠persona の両 ID audit 記録 (`both-ids-in-audit`、単一行 2 列) + `persona-switch-passes-four-eyes-visibly` (`03 §4`: 同一 operator が persona 切替で入力者承認→承認者承認すると四眼を通過し、**2 audit 行が同一 `session_operator_id` を共有** = honest-framing の cross-row 検証、単一行 dual-id とは別 test)。
  - **state**: `T-STATE` 離散 (per-action 前提条件、catch-all 不可) + idempotency family (`T-IDEMPOTENT`/`T-DUP`/`T-DOUBLE`/`T-RESOLVED`/`T-NOT-PAUSED`/`T-INCOMPLETE`) + `T-BULK-SELF`/`T-BULK-FLAGS` (partial-success)。

## 承認 gate (停止して user 判断)
1. **着手前**: branch `postv5/p1a-server` 作成 + PR 分割計画の確認 (本 §作業項目 を base に critical-review)。
2. **P1a 完了**: 上記 verification gates 全通過を証跡付きで提示 → PR → user 承認。**承認まで P1b に入らない**。
